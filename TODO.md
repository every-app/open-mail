Decisions taken by default while porting cloudflare/agentic-inbox to Every App (as OpenMail); each says what was decided, the default taken and the alternative.

- [ ] **Named OpenMail, app id `openmail`** (Ben, 2026-10-26): Apache-2.0 §6 grants no trademark rights, so the fork doesn't ship as "Agentic Inbox"; the README's Origin line credits cloudflare/agentic-inbox and says it is modified, and LICENSE stays upstream's (upstream has no NOTICE). The id is `openmail`, not `mail`, because `mail.<domain>` is commonly a mail host. A copy deployed as `agentic-inbox` is a different app to the gateway: deploy `openmail`, move mailboxes over, then `everyapp delete agentic-inbox`. Alternative: keep the old id and only rename the display name.
- [ ] **pnpm with `link:` dependencies on the platform checkout.** `@every-app/sdk` and `everyapp` are `link:../private-every-app/packages/{sdk,cli}` (publishing is paused), so the venue installs only with the platform checkout beside it, and CI can't install it. Alternative: published packages once publishing resumes.
- [ ] **Platform default compatibility date (2026-06-01); React Router 7.13.1 with a build shim.** `vite.config.ts`'s `reactRouterBuildOutputShim` mirrors React Router's client manifest because the Cloudflare Vite plugin 2.x writes the client build into the Build Output (React Router 8.4.0 fails identically). Alternative: drop the shim once React Router reads the client environment's `outDir` (upstream issue to file with remix-run/react-router and cloudflare/workers-sdk).
- [ ] **`env.AI` and `env.EMAIL` are shims inside `withGateway()`** (`workers/everyapp/gateway.ts`), so upstream's `lib/*`, Durable Objects and `email()` stay byte-identical. The AI client is created on the first model call, so a request never fails for want of an AI key. Alternative: rewrite each call site against the SDK.
- [ ] **`env.EMAIL` is the SDK's `sendEmail()` behind a `send_email`-shaped adapter** (`workers/everyapp/email.ts`): deployed, it posts to the gateway's `POST /api/integrations/email/send` over the `EVERY_APP_GATEWAY` binding, attributed to the request's person (the send routes) or the organization's background work; under `everyapp dev` the SDK checks the message and the manifest's senders as the gateway would and prints the mail (or sends it through Email Sending's REST API with `EMAIL_REST_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` and `EMAIL_FROM` in `.dev.vars`); a Worker with neither the binding nor dev refuses with `email_not_configured`. Every failure becomes `{ code, status, message }` with the gateway's code. Alternative: call `sendEmail()` from each route (edits upstream's `email-sender.ts` and `lib/tools.ts`).
- [ ] **Sends are awaited; a refusal answers 502 with the gateway's code and writes no Sent copy.** `POST …/emails`, `…/reply` and `…/forward` await `env.EMAIL.send()` and answer `502 { error: <code>, message }` when it fails (`email_sender_not_allowed`, `email_budget_exhausted`, `email_not_configured`, `email_send_failed`, …); the Sent row (and, for a reply, the thread's read mark) is written only after the gateway accepted the message, and success answers `200 { id, status: "sent" }` instead of `202`. Attachments are stored before the send (that decodes them) and deleted again when it fails. Alternative: upstream's `202` + `waitUntil`, which made a refused sender or an exhausted budget look like success.
- [ ] **`GET /api/v1/config` carries `ready`**: `integrationStatus({ env, provider: "email" })` (the gateway's `GET /api/integrations/email`) is `ready` **and** its effective `senders` are not empty, cached per isolate for 60 s. Every mailbox sends as itself, never as the gateway's sender, so a gateway that accepts none of the app's senders (a hosted gateway in v1) can't send for it. Under `everyapp dev` it is `true` only with `EMAIL_FROM` in `.dev.vars` (otherwise sends are printed, not sent). Alternative: the gateway's `ready` alone, and a refusal on first send.
