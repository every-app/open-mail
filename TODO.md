# TODO

## Decide

Decisions taken by default while porting agentic-inbox to Every App; each says what was decided, the default taken and the alternative.

- [ ] **pnpm with `link:` dependencies on the platform checkout.** `@every-app/sdk` and `everyapp` are `link:../private-every-app/packages/{sdk,cli}` (publishing is paused), so the venue installs only with the platform checkout beside it, and CI can't install it. Alternative: published packages once publishing resumes.
- [ ] **Platform default compatibility date (2026-06-01); React Router 7.13.1 with a build shim.** `vite.config.ts`'s `reactRouterBuildOutputShim` mirrors React Router's client manifest because the Cloudflare Vite plugin 2.x writes the client build into the Build Output (React Router 8.4.0 fails identically). Alternative: drop the shim once React Router reads the client environment's `outDir` (upstream issue to file with remix-run/react-router and cloudflare/workers-sdk).
- [ ] **`env.AI` and `env.EMAIL` are shims inside `withGateway()`** (`workers/everyapp/gateway.ts`), so upstream's `lib/*`, Durable Objects and `email()` stay byte-identical. The AI client is created on the first model call, so a request never fails for want of an AI key. Alternative: rewrite each call site against the SDK.
- [ ] **Until the gateway email capability is wired, `env.EMAIL` is a stand-in that logs in dev and refuses when deployed** (`code: "email_not_configured"`), so a deployed Worker never reports a send that didn't happen. Alternative: log-and-succeed everywhere (what the plan sketched).
- [ ] **Only the chat agent is reachable under `/agents/*`.** The guard compares partyserver's `lobby.className`, which in partyserver 0.3.3 is the env binding's name (`EMAIL_AGENT`), not the class name. Alternative: none; `MAILBOX` and `EMAIL_MCP` must stay internal.
- [ ] **`@modelcontextprotocol/sdk` is a direct dependency while `EmailMCP` exists, and `workers-ai-provider` stays until the agent moves to the gateway model.** pnpm doesn't hoist `agents`' copy of the MCP SDK for the app's own import. Alternative: none; both go with their last importer.
- [ ] **One `tsconfig.json` for the Worker, the React app and the config files.** `cf workers types` writes `.cloudflare/types/index.d.ts`, which imports `cloudflare.config.ts`, so the config files are in the Worker's program anyway; `tsc --noEmit` checks it all. Alternative: upstream's three project-reference configs with `tsc -b`.
- [ ] **`react-router typegen --mode development`.** Typegen loads `vite.config.ts`, whose Cloudflare plugin builds the Worker definition; production mode needs `.everyapp/deploy.json`, which only `everyapp deploy` writes. Alternative: none needed.
- [ ] **Inline images are `data:` URLs the page fetches** (`rewriteInlineImages`/`useInlineImages` in `app/lib/utils.ts`). The message iframe is a sandboxed `srcdoc` without `allow-same-origin`, so its own requests carry no gateway session and attachment URLs would answer 401. Each image is capped at 2 MiB; oversized and non-image inline parts are listed as attachments instead; the type must be a plain `type/subtype`. Alternative: signed short-lived attachment URLs (a public route), or `allow-same-origin` (gives the email's scripts the app's origin; no).
- [ ] **A 401 reloads the page, at most once per 10 s** (`app/services/api.ts`), so an ended session goes through the gateway's sign-in; the guard stops a reload loop if the gateway keeps answering 401. Alternative: an in-app "session ended" dialog with a sign-in link to `gatewayUrl`.
- [ ] **Refusal codes read as sentences in the client** (`ApiError` maps the gateway's `email_*` codes, `integration_not_configured` and `admin_required`; an unknown code shows the gateway's `message`). The compose dialog and the draft send show them unchanged. Alternative: the Worker rewrites the message before answering 502.
- [ ] **The readiness banner is on the home page only** (`config.ready === false`). Alternative: also in the compose panel, once members are seen composing without visiting home.
- [ ] **The MCP panel shows both endpoints**: the gateway's `/mcp` (from `/api/v1/me`'s `gatewayUrl`; OAuth sign-in or a personal access token) and the app host's `/mcp` (a personal access token), with a link to the gateway's Tokens page. Alternative: the gateway connector only, once L6's catalog replaces `EmailMCP`.
- [ ] **An organization's own copy first.** `everyapp deploy` pins the Worker to one organization (`EVERY_APP_ORG_ID`). The shared first-party shape (`--shared`) needs mailboxes scoped by organization, a domain-to-organization index for inbound mail and per-organization sending domains; nothing in the port rules it out, and until then the runbook says not to deploy with `--shared`. Alternative: build the shared shape now.
- [ ] **Workers AI through the gateway's AI proxy** (the `workers-ai` provider, platform PR 1). `AI_PROVIDER=openrouter` is the one-variable fallback, and the local way to exercise streaming and tools without a Workers AI token. Alternative: OpenRouter by default.
- [ ] **The agent's model defaults to `@cf/meta/llama-4-scout-17b-16e-instruct`** (300 requests a minute, function calling; safe with PR 1's response normaliser). `@cf/moonshotai/kimi-k2.6` (what the deprecated `kimi-k2.5` aliases to; paid-only, 20 requests a minute per account) is one `AGENT_MODEL` away. The scanner is `llama-3.1-8b-instruct-fast` and the verifier `llama-4-scout`, both non-streaming through the `run()` shim, which sends `max_tokens`/`temperature` only, never `stream_options`. Alternative: upstream's Kimi.
- [ ] **Sends are awaited.** A refusal answers 502 with the gateway's code and writes no Sent copy (upstream's `202` + `waitUntil` hid refused senders and spent budgets). Alternative: upstream's fire-and-forget.
- [ ] **Sending domains come from the manifest (`capabilities.email.senders`)**, `DOMAINS` is derived from them at build time, and the readiness banner reads the gateway's email status; no `EMAIL_SENDING_DOMAINS` gateway secret. Until platform PR 3 merges, `DOMAINS` comes from `INBOX_DOMAINS` at deploy and the deployed Worker refuses sends. Alternative: a gateway-wide sender list.
- [ ] **The inbound rule is a manual catch-all step** (dashboard or `cf email-routing rules catch-all update`) until platform PR 6 lets `everyapp deploy` create it. The `email` trigger stays refused, `receiveEmail` is byte-identical, `EMAIL_ADDRESSES` is fixed to `[]`. Alternative: a gateway-owned `email` trigger relaying `message.raw` (the fallback if a rule can't target a route-less Worker).
- [ ] **MCP is a `defineTools()` catalog with `PlainToolSchema` built from `zod/v4`'s `toJSONSchema`** (zod 3.25.76 stays; no override bump). `EmailMCP` and `mcp: "app"` go in the same change once the catalog test passes; `delete_email` is destructive and hidden. Alternative: keep the app's own `EmailMCP` behind `mcp: "app"`.
- [ ] **The organization is the boundary; roles come from the token.** Owners and admins create and delete mailboxes and edit settings (including the agent prompt); members read, draft, send and organise; no per-mailbox permissions; `access: "everyone"`. Alternative: per-mailbox ACLs.
- [ ] **Durable Object names stay the email address and R2 keys are unchanged**; the organization isn't stored on the mailbox JSON in this shape (it arrives with `--shared`). Alternative: organization-prefixed names now.
- [ ] **Agent sockets live 15 minutes** (a Durable Object alarm closes them; the client reconnects through the gateway). **Inline images are `data:` URLs** the parent fetches (2 MiB each at most), since the sandboxed iframe carries no gateway session. Alternative: no socket lifetime; images through a public route.
- [ ] **Vitest stays on 3.2 (the platform's version), with `@cloudflare/vitest-pool-workers` pinned to 0.12.21**, the last release for Vitest 3 (deprecated in favour of `@cloudflare/vitest-plugin`, which needs Vitest 4). Its workerd caps the test compatibility date at 2026-03-10, while production runs 2026-06-01. Alternative: Vitest 4 with `@cloudflare/vitest-plugin`, which lifts the date; move when the platform does.
- [ ] **The workers test project runs the production entry (`workers/app.ts`) with shared storage.** Isolated storage can't undo SQLite Durable Objects that are still open, and `receiveEmail()` always wakes `EmailAgent`, so tests use a fresh mailbox address each. The Durable Object bindings come from the manifest. Alternative: isolated storage with `EMAIL_AGENT` stubbed out of the env.
- [ ] **No CI workflow in the venue.** The `link:` dependencies need the platform checkout beside it, and the venue has no remote. Alternative: a workflow that checks out `every-app/private-every-app` beside it (needs a token for the private repository), or published packages once publishing resumes.
- [ ] **The README's setup is Every App's**; upstream's Deploy to Cloudflare and Cloudflare Access instructions are gone, and `docs/EVERY_APP.md` is the runbook. `pnpm check:runbook` checks its gateway secrets against the CLI. Alternative: keep upstream's README and add a section.
